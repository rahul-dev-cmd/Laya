# Laya: Dashboard API Data Contract

This document defines the data contract for Laya's analysis pipeline and dashboard integration. The contract specifies the JSON payload generated by `src/pipeline/analyze.py` for downstream visualization, temporal grounding overlays, and explanatory speech coaching feedback.

---

## Analysis Entry Point

```python
from src.pipeline.analyze import analyze

result = analyze(
    audio_wav="path/to/participant.wav",
    transcript_txt="path/to/transcript.txt",
    reference_wav="path/to/reference.wav",  # Optional: omit for experimental mode
    whisper_model="small.en",              # Optional: tiny.en, base.en, small.en, medium.en
    transcript_source=None,                # Optional: "provided", "auto", or "edited"
)
```

### Analysis Modes
* **`paired`**: Active when `reference_wav` is provided. Flaws are grounded contrastively against the reference take of the same speaker / passage (Mode A).
* **`experimental`**: Active when `reference_wav=None`. Flaws are diagnosed relative to the participant's internal speech distribution across the clip (Mode B: speaker median and MAD).

---

## Top-Level Schema

| Field | Type | Description |
| :--- | :--- | :--- |
| `mode` | `string` | Either `"paired"` or `"experimental"`. |
| `mode_note` | `string \| null` | Explanatory note if paired mode switched to experimental (e.g. match rate < 60%), otherwise `null`. |
| `duration` | `float` | Duration of the participant audio recording in seconds. |
| `audio_file` | `string` | Resolved file path to the participant audio WAV. |
| `reference_file` | `string \| null` | Resolved file path to reference audio WAV, or `null` if unassisted. |
| `transcript_source` | `string` | One of `"provided"`, `"auto"`, or `"edited"`. |
| `transcript` | `string` | Full transcript text used for forced alignment and speech analysis. |
| `word_match_rate` | `float \| null` | Proportion of words matched between participant and reference via difflib (0.0 to 1.0), or `null`. |
| `words` | `array[object]` | Chronological word list with forced alignment timestamps and confidence values. |
| `curves` | `object` | Frame-level continuous acoustic feature curves at a uniform 10 ms hop (100 Hz). |
| `flaw_regions` | `array[object]` | Temporal flaw intervals identified by frozen detector rules ($|z| \ge 2.0$). |
| `rubric` | `object` | Delivery rubric score payload with overall and dimensional scores. |

---

## Sub-Schema Details

### 1. `words` (Word-Level Alignment)
Array of aligned tokens:
```json
[
  {
    "word": "However",
    "start": 53.900,
    "end": 54.280,
    "confidence": 0.945
  },
  {
    "word": "this",
    "start": 54.280,
    "end": 54.420,
    "confidence": 0.880
  }
]
```
* `word` (`string`): The spoken word token (stripped of surrounding punctuation).
* `start` (`float`): Start timestamp in seconds.
* `end` (`float`): End timestamp in seconds.
* `confidence` (`float`): Alignment confidence score between 0.0 and 1.0.

---

### 2. `curves` (10 ms Frame-Level Acoustic Contours)
Uniformly sampled at a 10 ms hop (0.010 s step, 100 Hz sampling rate).

#### Schema of `curves`
* **`timestamps`** (`array[float]`): Time in seconds `[0.000, 0.010, 0.020, ...]` corresponding to frame centers for the participant recording.
* **`f0_semitones`** (`array[float | null]`): Pitch contour of participant in semitones relative to speaker's median F0 ($12 \cdot \log_2(\text{F0} / \text{median})$). Unvoiced frames are `null`.
* **`energy_z`** (`array[float]`): Frame-level RMS energy contour of participant, z-scored across the entire participant clip ($(\text{dB} - \mu) / \sigma$).
* **`speech_rate`** (`array[float]`): Speech rate in words per second evaluated over a 3.0 s sliding window centered across the participant audio timeline.
* **`participant`** (`object`): Explicit container grouping all acoustic curves of the participant recording:
  * `time` (`array[float]`): Participant timestamps in seconds `[0.000, 0.010, 0.020, ...]`.
  * `f0_semitones` (`array[float | null]`): Participant F0 in semitones relative to participant median F0.
  * `energy_z` (`array[float]`): Participant z-scored RMS frame energy.
  * `speech_rate` (`array[float]`): Participant speech rate in words/second (3.0 s sliding window).
* **`reference`** (`object | null`): Corresponding acoustic curves for the reference recording when in `"paired"` mode; `null` when in `"experimental"` mode:
  * `time` (`array[float]`): Reference timestamps in seconds `[0.000, 0.010, 0.020, ...]`.
  * `f0_semitones` (`array[float | null]`): Reference F0 in semitones relative to reference median F0.
  * `energy_z` (`array[float]`): Reference z-scored RMS frame energy.
  * `speech_rate` (`array[float]`): Reference speech rate in words/second (3.0 s sliding window).

#### Architectural Rationale: Why `participant` and `reference` Exist Beside Top-Level Curves
The `curves` object provides both top-level keys (`timestamps`, `f0_semitones`, `energy_z`, `speech_rate`) and nested objects (`participant`, `reference`) for two distinct operational reasons:
1. **Convenience & Direct Chart Binding**: Top-level keys act as a direct, unnested alias bound to the primary participant audio. Downstream visualization libraries (e.g. Chart.js, D3, Canvas renderers) can map directly to `data.curves.timestamps` and `data.curves.f0_semitones` without null-checking or digging into nested namespaces.
2. **Dual-Timeline Contrastive Overlay**: In `"paired"` mode, coaching requires simultaneously rendering the participant's take against the reference take. However, speech tempos naturally differ: the reference take generally has a different duration and distinct word timings than the participant take. Consequently, `reference.time` and `participant.time` are independent arrays of different lengths. Grouping each take under its own namespace (`participant` vs `reference`) preserves clean acoustic provenance, prevents timeline array collision, and allows `reference` to cleanly evaluate to `null` in unassisted experimental mode.

### 3. `flaw_regions` (Grounded Temporal Deviations & Scored Metrics)
Array of flagged temporal intervals sorted chronologically by `start`. Each entry carries the full grounded metrics and detector statistics behind its score:

```json
{
  "type": "rate",
  "start": 53.904,
  "end": 57.025,
  "peak_z": 4.697,
  "severity": "tier 5 (severe)",
  "peak_window_start": 53.900,
  "peak_window_end": 56.900,
  "observed_value": 6.00,
  "unit": "words/s",
  "baseline_mean": 3.1802,
  "baseline_spread": 0.6003,
  "threshold": 2.0,
  "reference_value": 3.67,
  "z": 4.697,
  "check": true,
  "null_reason": null,
  "explanation": "Speech rate accelerated to 6.00 words/s in peak window [53.90s-56.90s] (reference: 3.67 words/s; baseline mean: 3.18 words/s, spread: 0.60 words/s, threshold: +2.00; z = +4.70, peak z = +4.70) between 53.90s and 57.02s."
}
```

#### Field Specifications:
* `type` (`string`): Flaw modality (`"rate"`, `"pitch"`, `"pause"`).
* `start` (`float`): Region onset timestamp in seconds.
* `end` (`float`): Region offset timestamp in seconds.
* `peak_z` (`float`): Peak normalized deviation ($z$-score) exceeding frozen detection thresholds ($|z| \ge 2.0$).
* `severity` (`string`): Standardized tier classification derived from $|z|$:
  * `tier 1 (slight)`: $|z| < 2.3$
  * `tier 2 (mild)`: $2.3 \le |z| < 2.8$
  * `tier 3 (moderate)`: $2.8 \le |z| < 3.5$
  * `tier 4 (high)`: $3.5 \le |z| < 4.2$
  * `tier 5 (severe)`: $|z| \ge 4.2$
* `peak_window_start` (`float | null`): Start timestamp in seconds of the 3.0 s sliding window where peak $z$ occurred. Set to `null` for point boundary events (pause flaws) that do not use sliding windows.
* `peak_window_end` (`float | null`): End timestamp in seconds of the 3.0 s sliding window where peak $z$ occurred. Set to `null` for point boundary events (pause flaws).
* `observed_value` (`float | null`): The measured acoustic quantity in that peak window or boundary:
  * For pitch: voiced F0 standard deviation in semitones.
  * For rate: speech tempo in words per second.
  * For pause: measured pause silence duration in seconds.
* `unit` (`string`): Unit of measurement (`"semitones"`, `"words/s"`, `"s"`).
* `baseline_mean` (`float`): Baseline mean value exactly as evaluated by the detector.
* `baseline_spread` (`float`): Baseline spread / dispersion (standard deviation or scaled MAD) used as the denominator in the detector's $z$-score calculation.
* `threshold` (`float`): Cutoff threshold used by the detector (e.g. `2.0` or `-2.0`).
* `reference_value` (`float | null`): The identical quantity measured in the same temporal window or word boundary of the reference recording in `"paired"` mode; `null` in `"experimental"` mode.
* `z` (`float`): Recomputed $z$-score calculated as $(\text{observed\_value} - \text{baseline\_mean}) / \text{baseline\_spread}$.
* `check` (`boolean`): Validation flag confirming that recomputed `z` equals `peak_z` within 0.01 tolerance (`abs(z - peak_z) <= 0.01`), otherwise `false`.
* `null_reason` (`string | null`): Human-readable explanation if any quantity cannot be computed (e.g., explaining why pause flaws have `null` peak windows), or `null` if all values are present.
* `explanation` (`string`): Deterministic template sentence embedding exactly these measured quantities, baseline comparisons, and timestamps without generative hallucination.

#### Field Specifications:
* `version` (`string`): Rubric configuration version string (e.g. `"1.0.0"`).
* `method` (`string`): Exact formula as plain text describing dimensional and overall calculations.
* `method_note` (`string`): Explanatory caveat: `"A score of 100 means the detectors flagged nothing. It does not prove the delivery was good."`
* `mode` (`string`): Analysis mode (`"paired"` or `"experimental"`).
* `reliability_note` (`string`): Mode-specific baseline comparison context note (`"Compared with an ideal recording of the same speech"` or `"Compared with a general baseline, so less reliable"`).
* `dimensions` (`array[object]`): List of dimension score objects:
  * `name` (`string`): Dimension name (`"Pace"`, `"Pitch variation"`, `"Pauses"`, or `"Loudness"`).
  * `score` (`float | null`): Computed dimension score rounded to one decimal place, or `null` if unscored.
  * `scored` (`boolean`): Whether this dimension is included in the overall score calculation.
  * `measured` (`boolean`): Whether this dimension was measured from acoustic data.
  * `reason` (`string | null`): Explanatory reason if the dimension is unscored or unmeasured.
  * `region_count` (`integer`): Number of detected flaw regions or boundary flags for this dimension.
  * `flagged_seconds` (`float | null`): Flagged audio duration in seconds for continuous dimensions (Pace, Pitch variation, Loudness).
  * `flagged_pauses` (`integer | null`): Count of flagged boundary events for discrete dimensions (Pauses).
  * `pauses_examined` (`integer | null`): Number of word gaps examined by the pause detector, or `null` if unrecorded.
  * `worst_z` (`float | null`): Normalized deviation of the worst flagged region in this dimension, or `null` if no flags.
  * `worst_severity` (`string | null`): Standardized severity tier classification of the worst flagged region, or `null`.
  * `criterion` (`string`): One sentence describing what delivery characteristic the dimension checks.
* `overall` (`float | null`): Unweighted arithmetic mean of scored dimensions rounded to one decimal place, or `null` if fewer than 2 dimensions are scored.

## Explanation Layer (`POST /api/report`)

The explanation service converts raw measurement numbers and flagged regions into plain-language feedback. It accepts the analysis JSON payload and returns structured feedback with verified numeric grounding.

### Endpoint: `POST /api/report`

**Request Payload:**
```json
{
  "duration": 94.98,
  "mode": "paired",
  "transcript_source": "auto",
  "example_id": "librivox_01_pitch_tier5",
  "flaw_regions": [
    {
      "type": "pitch",
      "start": 54.58,
      "end": 58.84,
      "z": -4.478,
      "severity": "tier 5 (severe)",
      "observed_value": 0.037,
      "unit": "semitones",
      "baseline_mean": 2.9295,
      "baseline_spread": 0.646,
      "threshold": -2.0,
      "explanation": "Pitch intonation is monotone / flat..."
    }
  ]
}
```

**Response Payload:**
```json
{
  "source": "ai",
  "summary": "We analyzed 94.98 seconds of speech and identified 1 delivery variation region involving pitch, with a peak deviation score of z = -4.48.",
  "what_happened": [
    "From 54.58s to 58.84s (4.26 seconds duration), the speaker's vocal inflection was exceptionally flat (tier 5 (severe)). Measured pitch standard deviation dropped to 0.037 semitones compared to the baseline average of 2.93 semitones (deviation z = -4.48)."
  ],
  "why_it_matters": "Listeners depend on melodic pitch inflection and predictable pause boundaries to absorb spoken ideas effortlessly. Monotone stretches make it difficult for listeners to identify key takeaways.",
  "practice_tips": {
    "pitch": [
      "Mark the central concept in each sentence and deliberately lift your pitch on that target word.",
      "Practice reading a short paragraph aloud with exaggerated storytelling intonation before returning to conversational level.",
      "Ensure the final word of declarative statements finishes on a gentle downward pitch cadence."
    ]
  },
  "caveats": "Analysis was compared directly against a paired reference take."
}
```

### Fallback Guarantee
If LLM credentials are unset, the provider returns an error, the call exceeds the 30-second timeout, or any extracted number fails ground-truth verification, the endpoint returns the deterministic template report with `source: "template"`.
